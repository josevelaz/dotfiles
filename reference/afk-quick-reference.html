AFK quick reference

Hand a running Pi session off to iMessage, answer it from your phone, and get it back. Everything below is taken from the extension in this checkout.

Scope: one session Transport: Photon Spectrum · iMessage Source: .pi/agent/extensions/afk/

The model in one line

AFK is a session-scoped handoff, not a remote terminal. It forwards specific question, blocked, and settled events. Your reply answers the question or continues that session.

  1. Stop 1 Your phone iMessage, from and to the number in PI_AFK_PHONE. Replies from any other number are ignored.
  2. Stop 2 Session key Eight characters, shown in session-specific texts and in the Pi footer. Broker-wide replies can omit it.
  3. Stop 3 The Pi session Answers its pending question, or takes your text as a user message and keeps going.

Commands and setup

Commands

Run inside the Pi session you are leaving
Command Effect
/afk on Turn the handoff on and connect. Pi replies with the session key.
/afk off Turn it off. Any pending question stops waiting on a text.
/afk status Report on/off, the session key, and whether Photon is connected or reconnecting.
/afk Toggle. Prefer the explicit forms.

The setting is stored in the session, so it survives a reload of that session and does not leak into other sessions. index.ts

Prerequisites

export PHOTON_PROJECT_ID="…"
export PHOTON_PROJECT_SECRET="…"
export PI_AFK_PHONE="+15551234567"
  • Photon project created and iMessage enabled.
  • Dependencies installed once: npm install --omit=dev in the extension directory.
  • All three variables must be exported before Pi starts.
  • You must be in the interactive Pi TUI.

README.md

Confirming it is on

The Pi status footer gains an accent-coloured item carrying your session key:

✉ afk 019f94f1

No footer item means AFK is off or suppressed in this process. Run /afk status to tell those apart. index.ts

When Pi texts you

Three triggers, and what a reply does in each case
Trigger What fires it You receive Your reply
Question The afk:question event, and only while AFK is on, the broker is connected, and no earlier question is still waiting. The question, the numbered choices, and one extra slot for your own answer. Answers the question and releases the run.
Blocked Two sources only: the herdr:blocked event becoming active, or a goal_report tool result with status blocked. Blocked: plus the reason. Becomes a user message that continues the session.
Idle agent_settled after a run has actually happened and the session is idle. A session that settles blocked sends no idle text. Pi is idle. plus a truncated summary of the last reply. Becomes a user message that starts the next turn.

These are subscriptions, not heuristics. Any other question, stall, or quiet moment produces no text. index.ts · protocol.ts

Reply grammar

A question with three choices. The custom slot is always choices + 1.
You send Result
2 Selects choice 2.
4 use the safer approach Answers in your own words. 4 is the custom slot.
2 merge it Rejected: Reply with only 2 to select that option. Text is allowed only after the custom slot.
4 Rejected: the custom slot needs your answer after it.
9 Rejected: out of range.
merge it Rejected while a question is pending: it does not start with a number.
Rule of thumb

A number alone picks a listed choice. A number plus text is only valid for the custom slot. A rejection is texted back and the question keeps waiting, so you can simply try again.

Routing with several sessions

How a reply is matched to a session, in order
Order Rule Example
1 A leading key that matches a session which is AFK right now wins, whatever else is true. 019f94f1 2
019f94f1 use the safer approach
2 A reply starting with a number goes to the one session waiting on a question, if exactly one is. 2
3 Otherwise, if exactly one session is AFK, it goes there. run the tests again
4 Otherwise the broker texts back the list of keys and delivers nothing. —

[019f94f1] 2 and 019f94f1: 2 also work; the brackets and separator are optional. The key is not case-sensitive. routing.mjs

A stale key is not rejected

Rule 1 only applies to a key that matches a currently active session. routing.mjs does not validate keys and does not bounce unknown ones — explicit matching falls through to rules 2 to 4. With exactly one session AFK, rule 3 then delivers the whole text, stale prefix included, to that session: as a user message if nothing is pending, or into the answer parser, which rejects it for not starting with a number.

So prefix with the key you can currently read — off the newest text, or off /afk status. A current key is the safest prefix. A remembered one is a guess that fails quietly.

Replying while Pi is busy

If no question is pending and the session is mid-run, your text is queued as a follow-up. It is delivered when the current turn ends. It does not interrupt a tool call and it does not stop the run. index.ts

Recovery

Nothing arrives on the phone

  • Suppressed process. AFK texts are off automatically outside the TUI, and are forced off by --no-afk-texts or PI_AFK_DISABLE=1. /afk status says suppressed.
  • Missing variables. Enabling fails with a notice naming PHOTON_PROJECT_ID, PHOTON_PROJECT_SECRET, and PI_AFK_PHONE. Export them and restart Pi.
  • Reconnecting. /afk status shows reconnecting instead of connected. The client retries on its own; a pending question is re-sent once the link returns.
  • Broker failed to start. Read the log: /tmp/pi-afk-<uid>.log.

The text bounces back

  • No Pi session currently has /afk enabled. — every session has closed or turned AFK off. Nothing is listening.
  • More than one Pi session is in AFK mode… — the reply was ambiguous. The bounce lists each key, label, and state. Resend with the key in front.
  • Reply with 1-N, or N+1 followed by… — the question is still open. Fix the grammar and resend.
  • Replies from a number other than PI_AFK_PHONE are dropped silently.

Protecting the secret

Do not commit this

PHOTON_PROJECT_SECRET belongs in your shell secret store and nowhere else. The extension reads it from the environment and passes it to the local broker through the process environment; it is never written into the repository or into the Pi session transcript. Keep it that way: do not paste it into a prompt, a config file, or a lesson. README.md

Related: set PI_AFK_DISABLE=1 in a subagent's environment only, so the parent session keeps its handoff while the child stays quiet.
