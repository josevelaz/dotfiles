Lesson 0001 · 5–8 minutes

Your first AFK handoff

By the end of this page you will know what AFK actually hands you, and you will be able to write a reply that lands in the right session on the first try.

Win: form a correct reply Mission: use it confidently Reference: quick reference

1. What AFK is, and what it is not

AFK is a session-scoped handoff. You are not getting a terminal on your phone. One Pi session texts you when the extension sees one of a small, named set of events — a Pi question routed through its afk:question integration, one of two specific blocked reports, or the session going idle after a run — and your reply goes back into that session. That is the whole surface.

This matters because it sets your expectations correctly. You cannot browse files, cancel a tool, or start a new session from iMessage. You can make the one decision the session is waiting on. Follow the tape:

  1. Stop 1 Your phone The single number in PI_AFK_PHONE. Messages from anywhere else are ignored.
  2. Stop 2 Session key Eight characters, e.g. 019f94f1. Shown in session-specific texts and in the Pi footer; broker-wide replies can omit it.
  3. Stop 3 The Pi session Answers its question, or takes your text as a message and continues the run.

Source: .pi/agent/extensions/afk/README.md and index.ts.

2. Before you can turn it on

Three things, once:

  1. A Photon project with iMessage enabled, from app.photon.codes.
  2. Three variables exported before Pi starts: PHOTON_PROJECT_ID, PHOTON_PROJECT_SECRET, PI_AFK_PHONE.
  3. Extension dependencies installed: npm install --omit=dev inside ~/.pi/agent/extensions/afk.
Protect the secret

PHOTON_PROJECT_SECRET lives in your shell secret store. The extension reads it from the environment and hands it to the local broker through the process environment; it is never written to the repository or into the Pi session. Do not paste it into a prompt or a config file to "test" it.

Source: README.md — Setup and Security.

3. Turn it on and check the footer

In the session you are about to walk away from:

/afk on

Pi confirms with the session key, and the status footer picks up an accent-coloured item:

✉ afk 019f94f1

That footer confirms AFK is enabled in this process. If it is absent, do not assume the handoff is active; check /afk status. Those eight characters are the same key you will type in front of a reply later, so read them once now. If you want the fuller picture — on or off, the key, and whether Photon is connected or reconnecting — ask: 

/afk status

Source: index.ts — updateStatus and showStatus; protocol.ts — shortSessionKey.

4. The three run-state alerts

AFK does not watch Pi for "anything that looks like a question" or "anything that looks stuck". Three specific subscriptions produce the run-state alerts below. AFK also sends operational texts when you enable it, when an answer is rejected, or when the broker needs routing clarification.

A question

The extension listens for the afk:question event. When one arrives, it claims the question and texts it to you — but only if AFK is on, the broker is connected, and no earlier question is still waiting. A question that is not raised through that integration, or that arrives while another one is unanswered, stays on the laptop.

  • Pi[019f94f1] dotfiles Question: The branch has diverged from main. How should I proceed? 1. Rebase onto main 2. Merge main into the branch 3. Stop and let me look 4. Type your own answer

The choices are numbered, and one extra slot is appended for an answer in your own words. Three choices means the custom slot is 4.

Blocked

Two sources, and no others. The extension listens for the herdr:blocked event becoming active, and for a goal_report tool result whose status is blocked. A run that is stuck for some other reason does not text you, because nothing reported it as blocked.

  • Pi[019f94f1] dotfiles Blocked: the test suite needs a decision.

Idle

This one is post-run only. On agent_settled, the extension texts you if a run actually happened since the last notice and the session is now idle. Sitting at an idle prompt without running anything sends nothing, and if the session settled in a blocked state you get no second idle text.

  • Pi[019f94f1] dotfiles Pi is idle. …the last thing the assistant said, truncated.

The difference matters for your reply. Only the first case is a question, and only a question uses the numbered grammar. In the other two, whatever you type becomes an ordinary user message that continues the session.

Source: index.ts — the afk:question and herdr:blocked event handlers, the goal_report branch of tool_result, and onAgentSettled.

5. How to form the reply

Three shapes cover everything you will type.

Pick a listed choice: the number alone

  • You2

Nothing else. Adding words after a listed number is rejected — you will get Reply with only 2 to select that option. back on your phone, and the question keeps waiting.

Answer in your own words: the custom slot plus text

  • You4 use the safer approach

The custom slot is always one past the last choice. It is the only number that accepts text after it, and it requires text — a bare 4 is rejected.

Several sessions AFK: key first

  • You019f94f1 2
  • You019f94f1 use the safer approach

A leading key that names a session which is AFK right now wins over every other rule, which makes a current key the safest prefix you can send. Without a key, a bare number only routes when exactly one session is waiting on a question, and plain text only routes when exactly one session is AFK at all. Otherwise the broker texts back the list of keys and delivers nothing.

A wrong key is not an error

routing.mjs does not validate keys. If the leading token does not match a session that is AFK right now, explicit matching just falls through to the remaining rules. With exactly one session AFK, that means the entire text — stale key included — is handed to that session: as an ordinary user message if nothing is pending, or straight into the answer parser, which rejects it because it does not start with a number. So read the key off the newest text or off /afk status. Never retype one from memory.

The one habit to build

Prefix your reply with the key you can currently see. Nine extra characters remove routing ambiguity when more than one session is AFK.

Source: protocol.ts — parseRemoteQuestionAnswer; routing.mjs — chooseTarget.

6. Replying while Pi is still working

If there is no pending question and the session is mid-run, your text is queued as a follow-up. It arrives when the current turn ends. It does not interrupt a tool call, and it will not stop a run that is heading somewhere you do not want.

So AFK is a good way to steer the next turn and a poor way to slam on the brakes. If you need to stop something, that is a laptop job.

Source: index.ts — handleInbound, deliverAs: "followUp".

7. Practice: route seven replies

Read each situation and type the exact text you would send from iMessage. The widget does not compare you against an answer key — it runs your reply through a local model of the extension's routing and parsing rules, then tells you where it would have landed.

Type from memory. Scrolling back up to copy the syntax feels productive and teaches you almost nothing.

8. Take the session back

When you sit down again:

/afk off

The footer item disappears and the texts stop. Any question that was waiting on a text stops waiting. You do not have to remember: shutting the session down unregisters it too, so a closed session cannot be texted. The real cost of leaving it on is the opposite one — a session you thought you were done with keeps texting you, and keeps competing for replies that carry no key.

9. When it does not work

Five checks, in the order worth trying.

Symptom to first move
Symptom First move
/afk on says texts are suppressed You are outside the interactive TUI, or the process was started with --no-afk-texts or PI_AFK_DISABLE=1. Standard non-TUI subagent runs are therefore suppressed.
/afk on names three variables PHOTON_PROJECT_ID, PHOTON_PROJECT_SECRET, or PI_AFK_PHONE is missing. Export them and restart Pi — exporting after Pi starts does not help.
/afk status says reconnecting The link to the broker dropped. It retries on its own, and a pending question is re-sent once the connection returns. Wait, then re-check.
Enabling fails outright Read the broker log at /tmp/pi-afk-<uid>.log, where <uid> is your numeric user id.
Your text bounces back No Pi session currently has /afk enabled means nothing is listening. More than one Pi session is in AFK mode means you omitted the key — the bounce lists the keys, so resend with one in front.

Source: client.ts, broker.mjs, index.ts.

Everything below that line is internals — a local broker process, a unix socket, a Photon connection shared between sessions. You do not need it to use AFK well. Ask about it when you are curious, not before.
